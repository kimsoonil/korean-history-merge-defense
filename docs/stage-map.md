# 스테이지 지도와 순차 개방

## 사용자 흐름

초기 화면의 새로하기 → 가로 지도 → 1 스테이지 지점 → 1-1~1-8 목록 → 개방된 전투 선택 → 전투 준비.

- 1-1~1-7: 수나라의 침공 / 1-8: 살수대첩.
- 1-1부터 이전 전투를 완료해야 다음 전투가 활성화됩니다. 완료한 전투는 다시 플레이할 수 있습니다.
- 스테이지 개방 기록은 게임 진행 저장과 분리하므로 새 게임을 시작해도 사라지지 않습니다.
- 2~10 스테이지 지점은 잠금 표시와 준비 중 안내를 제공합니다. 아직 전투를 실행하지 않으며 이전 스테이지 클리어 조건도 안내합니다.
- 지도를 둘러보고 닫는 것만으로 기존 이어하기 기록을 바꾸지 않습니다. 새 전투 실행 직전에만 기존 기록 교체를 확인합니다.

## 지도

`app/StageMap.tsx`의 독자적인 SVG 바다·숲·산·성곽 지형 위에 10개의 HTML 버튼 지점을 배치합니다. 점선 경로는 지점과 같은 좌표 데이터를 사용하므로 화면 크기가 바뀌어도 연결됩니다. 지형과 지점은 함께 스크롤되며 처음 화면 밖의 전장까지 탐색할 수 있습니다. 실제 역사 지리를 재현한 지도가 아닌 게임용 판타지 지도입니다.

마우스 휠의 세로 입력을 가로 이동으로 변환하고, 트랙패드의 가로 입력도 지원합니다. PC 마우스 드래그, 모바일 스와이프, 하단 이동 버튼, 키보드 좌우 화살표 및 Home/End를 제공합니다. 브라우저 확대 제스처는 가로 스크롤로 가로채지 않습니다. 팝업이 열리면 뒤쪽 지도와 헤더의 조작을 막습니다.

## 전투 및 저장

- 공통 정의는 `lib/campaign.ts`에 있습니다. 최종 전투는 8이며, 수양제는 기존과 같은 4,890 HP와 보스전 BGM을 유지합니다. 게임 UI·출현·보상·승리 판정이 동일한 상수를 사용합니다.
- 개방 기록 키: `salsu-campaign-v1`, 형식: `{version:1,highestClearedWave:0..8}`.
- 진행 저장 키는 `salsu-progress-v1`을 유지하고 내부 포맷 버전을 2로 올렸습니다. 유닛·자원을 잃지 않도록 구버전 기록을 변환하며, 구버전에서 이미 도달한 전투의 이전 전투들은 완료한 것으로 인정합니다.
- 구버전 1-8/1-9 진행은 새 1-8 준비 화면으로, 구버전 1-10은 새 1-8 동일 전투 상태로 이어집니다.
- 보상 지급 완료와 스테이지 개방은 중복 처리하지 않습니다. 아직 열리지 않은 전투는 화면뿐 아니라 시작 처리에서도 검사합니다.

## 자동 검증

`npm run lint`, `npm run build`, `node --test tests/*.test.mjs`를 사용합니다. 지도 10개 지점과 좌표, 가로 휠 변환, 전투 이름, 순차 개방·기록 복원, 기존 저장 변환, 1-8 보스 생성·체력·음악 조건을 포함합니다.

실제 브라우저 검증: PC 지도에서 세로 휠 입력으로 가로 위치가 720px 이동하고, End 키로 마지막 지점에 도달하여 10번 준비 중 안내를 확인했습니다. 320×568에서는 드래그로 가로 210px 이동하고 페이지 세로 스크롤은 발생하지 않았습니다. 같은 화면에서 8개 전투 목록이 내부 스크롤 없이 모두 표시됩니다. 실제 1-1을 클리어한 뒤 새로고침하여 1-2만 새로 개방됨을 확인했으며, 1-1을 새 게임으로 다시 시작한 후에도 1-1 클리어·1-2 개방 기록이 유지되었습니다. 보스 1-8 조건과 구버전 저장 변환은 자동 테스트로 검증했습니다.
